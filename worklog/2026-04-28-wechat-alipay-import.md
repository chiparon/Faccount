# 2026-04-28 wechat alipay import

## 目标
- 用户更新了 `pageref/` 下支付宝与微信导出账单，需要完善导入识别和缓存逻辑。

## 实际修改
- 识别真实示例文件：
  - `pageref/支付宝交易明细(20260401-20260428).csv`
  - `pageref/微信支付账单流水文件(20260401-20260428)_20260428202807.xlsx`
- 支付宝 CSV 结构：前 24 行为导出说明，第 25 行从 `交易时间,交易分类,交易对方,对方账号,商品说明,收/支,金额,收/付款方式,交易状态...` 开始。
- 微信 XLSX 结构：前 15 行为导出说明，第 16 行从 `交易时间,交易类型,交易对方,商品,收/支,金额(元),支付方式,当前状态...` 开始；交易时间为 Excel 序列号。
- 重写 `frontend/src/pages/ImportCachePage.vue`：
  - 支持支付宝 CSV 与微信 XLSX。
  - 自动跳过说明行，定位包含 `交易时间` 的真实表头。
  - 自动识别来源：`alipay` / `wechat` / `unknown`。
  - 将账单行转换为应用内流水草稿。
  - 支持编辑草稿名称、金额、时间、类型、分类、账户、备注。
  - 支持批量选择后压入流水池。
  - 支持撤销已压入批次，撤销时把创建的流水移入 Trash。
  - 保留原始字段预览，便于核对导入识别结果。
- 支付宝映射规则：
  - `商品说明` 优先作为流水名称，缺失时用 `交易对方`。
  - `交易分类`、商品说明、交易对方用于猜测分类。
  - `收/付款方式`、交易状态、订单号进入备注。
- 微信映射规则：
  - `商品` 优先作为流水名称，缺失时用 `交易对方`。
  - `交易类型`、商品、交易对方用于猜测分类。
  - `支付方式`、当前状态、交易单号进入备注。
- 为避免 `xlsx` 包带来的高危依赖审计问题，改用 `fflate` 解压 XLSX 并用浏览器 `DOMParser` 读取 sheet/sharedStrings。
- 更新 `frontend/package.json` 与 `frontend/package-lock.json`，新增依赖 `fflate`。
- 更新 `frontend/src/styles/main.css`，补充导入草稿编辑区、批次操作区和原始预览样式。

## 验证结果
- 前端构建通过：`npm run build`。
- 前端依赖审计通过：`npm audit --audit-level=high`，结果 `found 0 vulnerabilities`。
- 后端测试通过：`5 passed`。

## 遗留问题
- 导入压入流水池时，仍需要用户为草稿指定账户和分类；分类猜测只是辅助。
- 中性交易/不计收支默认不自动压入，需要用户手动改为收入或支出后提交。
- 撤销已压入批次目前是把对应流水移入 Trash，而不是永久删除。
